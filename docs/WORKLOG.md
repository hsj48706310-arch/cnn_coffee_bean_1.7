# 📘 프로젝트 작업 일지 — 초보자도 이해하는 버전

> **목표**: 커피 원두 사진을 보고 컴퓨터가  
> ① **얼마나 볶았는지** (로스팅 단계)  
> ② **어떤 결점이 있는지** (결점두 종류)  
> 를 자동으로 맞히는 AI를 만든다.

> 어려운 단어는 ⓘ 표시 → **맨 아래 [📖 용어집](#-용어집)에서 설명**

---

## 🎯 한 문장 요약

> 처음엔 점수가 100점(F1=1.0) 나와서 "와 잘된다!" 했는데,  
> 알고 보니 **데이터가 너무 쉬워서** 어떤 모델을 써도 100점이 나오는 거였어요.  
> 그래서 **진짜 어려운 문제(결점두 17종 분류)** 로 갈아탔고,  
> **F1 0.79점** 을 정직하게 달성했어요.  
> 그리고 모델을 **5배 빠르게** 만드는 작업까지 마쳤습니다.

---

## 🗓️ 작업 순서 (시간순)

### 🟢 1단계 — 첫 시작: "일단 돌아가는지 보자"

**왜 했나?**  
새 프로젝트는 처음부터 욕심내면 망해요. 가장 단순한 문제부터 시작해서  
**"내가 만든 코드가 일단 학습이 되긴 하는가?"** 부터 확인해야 합니다.

**무엇을 했나?**
- 캐글ⓘ 에서 커피 원두 사진 1,600장을 다운로드
- 4종류로 분류: `green`(생두) / `light`(약볶음) / `medium`(중볶음) / `dark`(강볶음)
- ResNet18ⓘ 이라는 가벼운 AI 모델로 학습ⓘ

**결과**
- 🎯 **테스트 점수: 100점 (F1=1.000)** ← 완벽!
- 😕 근데 너무 잘 나옴. **"이게 진짜인가?"** 라는 의심이 생김.

---

### 🟡 2단계 — 더 좋은 모델로 바꿔보기

**왜 했나?**  
ResNet18은 2015년 모델이라 좀 오래됐어요. **요즘 모델이면 더 잘하지 않을까?** 호기심.  
그리고 발표할 때 "최신 모델 썼어요" 가 더 그럴듯해 보임.

**무엇을 했나?**
- 모델만 EfficientNet-B0ⓘ 로 바꿈 (더 똑똑하다고 알려진 모델)
- 데이터, 학습 방법은 그대로

**결과**
- 🎯 **또 100점**
- ❗ **결론**: 모델을 바꿔도 100점이 나온다는 건  
  → **모델이 잘난 게 아니라, 문제 자체가 너무 쉽다는 뜻**.  
  마치 1+1을 누가 풀어도 다 맞히는 것처럼요.

---

### 🟠 3단계 — 진짜 어려운 문제 가져오기

**왜 했나?**  
시험에서 100점 자랑하면 "쉬운 시험 풀었네" 라는 말 듣잖아요?  
발표에서도 똑같아요. **"우리가 어려운 문제도 풀 수 있다"** 를 보여줘야 해요.

그래서 **결점두**ⓘ 분류로 갈아탔습니다. 이건:
- 17종류로 분류해야 함 (4종류보다 4배 많음)
- 사람 눈으로도 구분이 어려운 미묘한 차이 (예: 약간 곰팡이 vs 심한 곰팡이)
- 진짜 커피 회사가 품질 검사할 때 쓰는 분류

**무엇을 했나?**
- 캐글에서 결점두 사진 약 6,000장 다운로드 (17종)
- 학습 코드를 **두 문제 다 쓸 수 있게** 일반화

**결과**
- ✅ 데이터 준비 완료
- ✅ 학습 시스템 준비 완료

---

### 🔴 4단계 — "정직한 비교"를 위한 데이터 줄이기

**왜 했나?**  
- 로스팅 사진은 1,600장, 결점두 사진은 6,000장 → **수가 다르면 비교가 불공정**
- 만약 결점두 점수가 잘 나와도 "데이터 4배 많으니까 당연하지" 라는 반박이 가능
- 그래서 **둘 다 1,000장 정도로 똑같이 맞춰서** 비교해야 함

**무엇을 했나?**
- 로스팅: 1,600장 → **1,000장**으로 줄임 (각 클래스에서 균등하게)
- 결점두: 6,000장 → **979장**으로 줄임 (17종에서 균등하게)

**결과** — 🤯 **여기서 진실이 드러남!**
- 로스팅 점수: **100점 → 94점**으로 떨어짐
  - → **이전 100점은 "데이터가 너무 많아서" 나온 거짓 만점**이었음을 증명
- 결점두 점수: **79점** (17종 분류치고 매우 좋은 점수)

이 단계가 우리 프로젝트의 **핵심 발견**입니다. 정직하게 측정하니 진짜 실력이 나왔어요.

---

### 🔵 5단계 — 똑똑하게 학습시키기 (2단계 학습법)

**왜 했나?**  
결점두 17종 분류는 어려운 문제라서 **그냥 학습**하면 잘 안 돼요.  
**단계를 나눠서 가르치면** 더 잘 배운다는 게 알려져 있어요.

비유하자면:
- ❌ 그냥 학습 = "수학 모르는 애한테 미적분 바로 가르치기"
- ✅ 2단계 학습 = "기초 산수부터 가르치고 → 그 다음 미적분"

**무엇을 했나?**
- **1단계 (워밍업, 2 epochⓘ)**: 모델의 대부분(특징 추출 부분ⓘ)은 동결ⓘ 시키고,  
  마지막 분류 부분만 학습 → "기초 익히기"
- **2단계 (본격 학습, 6 epoch)**: 동결을 풀고 전체 모델 학습 → "응용까지 익히기"

**결과** — 학습 곡선에 **2단계 효과가 명확히 보임**:
```
[E01] 동결    F1=0.44  ← 워밍업 시작
[E02] 동결    F1=0.56  ← 기초 익힘
[E03] 동결해제 F1=0.47  ← 잠깐 떨어짐 (적응 중)
[E04] 동결해제 F1=0.72  ← 점프! (응용 시작)
[E05] 동결해제 F1=0.73
[E06] 동결해제 F1=0.75
[E07] 동결해제 F1=0.80  ← 최고점!
[E08] 동결해제 F1=0.78  ← 약간 떨어짐 (수렴)
```

E07 시점에서 가장 좋은 모델을 자동 저장했습니다.

---

### 🟣 6단계 — "어떤 결점은 잘하고 어떤 건 못 하나?" 분석

**왜 했나?**  
평균 점수만 보면 모델이 어디서 헷갈리는지 모르겠어요.  
발표에서 **"이런 건 잘하고, 이런 건 못해요"** 를 구체적으로 보여줘야 신뢰도 ↑

**결과 — 17종을 난이도별로 분류**

| 🟢 잘 맞힘 (F1≥0.85) | 🟡 보통 (0.70~0.85) | 🔴 어려움 (<0.70) |
|---|---|---|
| dry cherry 1.000 (말린 체리) | cut 0.778 (자른 결점) | full sour 0.700 (전체 신맛) |
| full black 1.000 (완전 흑변) | fungus 0.750 (곰팡이) | partial sour 0.706 (부분 신맛) |
| husk 1.000 (껍질) | immature 0.714 (미성숙) | **fade 0.429 (옅은 변색)** |
| broken 0.941 (깨짐) | severe insect 0.714 (심한 벌레) | **withered 0.375 (쪼그라듦)** |
| shell 0.941 (조개껍질형) | slight insect 0.800 (약한 벌레) | |
| floater 0.857 (뜬 콩) | partial black 0.818 (부분 흑변) | |
| parchment 0.857 (얇은껍질) | | |

**인사이트**:
- 🟢 **잘 맞히는 결점**: 색이나 모양이 **확실히 다른 것** (검은색, 껍질 등)
- 🔴 **못 맞히는 결점**: `withered`(쪼그라듦), `fade`(옅은 색변) → **정상 콩이랑 거의 비슷해 보임**
- 🤔 **자주 헷갈리는 짝**: `partial sour ↔ full sour`, `약한 벌레 ↔ 심한 벌레`  
  → 같은 결점의 **정도 차이** → 사람도 헷갈릴 수 있는 부분 (한계 인정)

---

### ⚡ 7단계 — 모델 빠르게 만들기 (ONNX 변환)

**왜 했나?**  
PyTorchⓘ 로 만든 모델은 학습엔 좋은데 **실제 서비스에는 무거워요**.  
실제로 공장에서 컨베이어 벨트 위 원두를 실시간 검사하려면 **빨라야 합니다** (초당 30장 이상).

ONNXⓘ 라는 표준 포맷으로 변환하면:
- 🚀 추론ⓘ 속도가 빨라짐
- 📱 다양한 환경에서 실행 가능 (모바일, 웹, IoT 등)

**무엇을 했나?**
- 두 모델 모두 ONNX 포맷으로 변환
- 변환 전후 속도 측정 (CPUⓘ 환경)

**결과**

| 모델 | 환경 | 한 장 처리 시간 | 초당 장수(FPSⓘ) | 가속 |
|---|---|---|---|---|
| 로스팅 | PyTorch | 21.30 ms | 47장 | 1.0× |
| 로스팅 | **ONNX** | **6.38 ms** | **157장** | **3.3배 빠름** |
| 결점두 | PyTorch | 23.34 ms | 43장 | 1.0× |
| 결점두 | **ONNX** | **4.74 ms** | **211장** | **4.9배 빠름** |

→ 목표인 30 FPS를 **5배 이상 초과** → 실시간 라인 검사기로 충분히 사용 가능

---

### 🎨 8단계 — 데모용 웹앱 만들기

**왜 했나?**  
모델은 만들었는데 **눈으로 보여줄 게 없으면** 발표가 재미없어요.  
Streamlitⓘ 으로 간단한 웹 화면을 만들면 **그 자리에서 시연** 가능.

**무엇을 했나?**
- 사이드바에서 **🔥 로스팅 / 🐛 결점두** 모델 토글
- 이미지 업로드 → 즉시 예측 + 확률 + Top-K 표시
- 한글 UI, CSV 다운로드 버튼

**결과**: `app/streamlit_app.py` 완성, `streamlit run app/streamlit_app.py` 로 실행

## 💡 팀원 설득 포인트 5가지

1. **"우리는 정직하게 평가했어요"**  
   → 100점 자랑 안 하고, 천장 효과를 직접 깨뜨려서 94점으로 보고. **신뢰성 있는 평가**.

2. **"진짜 어려운 문제로 확장했어요"**  
   → 17종 결점두 분류는 실제 산업에서 쓰이는 문제. **F1 79점은 매우 의미 있는 숫자**.

3. **"실제 서비스 가능한 수준이에요"**  
   → ONNX 변환으로 4.9배 가속, 초당 211장 처리 → **공장 라인에서 실시간 검사 가능**.

4. **"바로 보여줄 데모가 있어요"**  
   → Streamlit 웹앱으로 그 자리에서 분류 시연 가능 (스크린샷만으로도 임팩트 충분).

5. **"한계도 솔직하게 분석했어요"**  
   → `withered`, `fade` 같은 미묘한 결점은 모델 한계 명확. **다음 스텝까지 제시**.

## 📖 용어집

> 위에서 ⓘ 표시가 붙은 단어들 설명입니다.

### 데이터 / 학습 관련

**캐글(Kaggle)**  
세계 최대 데이터 분석 / AI 경진대회 플랫폼. 무료 데이터셋이 엄청 많아서 연구/학습용으로 자주 씁니다.  
이 프로젝트는 캐글의 커피 원두 데이터셋 2개를 사용했습니다.

**학습 (training)**  
AI 모델한테 "이 사진은 light야", "이 사진은 dark야" 라고 정답을 알려주면서  
**스스로 패턴을 찾도록 시키는 과정**. 사람이 단어를 외우는 것처럼 모델이 데이터를 외웁니다.

**Epoch (에폭)**  
학습 데이터 **전체를 한 번 다 본 것** = 1 epoch.  
예: 700장짜리 데이터를 8 epoch 학습 = 700장을 8번 반복해서 봄.

**검증(Validation) / 테스트(Test) 데이터**  
- **검증**: 학습 중간중간 "지금까지 잘 배웠나?" 확인용 데이터 (150장)
- **테스트**: 학습 다 끝난 후 **최종 성적** 매기는 데이터 (150장, 학습엔 절대 안 씀)
- 시험 비유하면: 검증=모의고사, 테스트=수능

**Stratified split (층화 분할)**  
데이터를 train/val/test로 나눌 때 **각 클래스 비율을 똑같이 유지**하는 방법.  
예: 4종류가 250장씩이면 → train에도 175장씩, test에도 37장씩 들어가도록 분할.

### 모델 관련

**ResNet18**  
2015년에 나온 유명한 이미지 분류 모델. 18층짜리 신경망으로 가볍고 빠름. **AI 입문용**으로 자주 씀.

**EfficientNet-B0**  
2019년에 나온 이미지 분류 모델. ResNet보다 작지만 더 정확. B0~B7까지 있는데 B0가 가장 작음.  
이 프로젝트의 메인 모델.

**특징 추출 부분 (backbone)**  
모델의 앞쪽 부분으로, 사진에서 **"이건 둥글고, 색은 갈색이고..."** 같은 특징을 뽑아내는 역할.  
ImageNetⓘ 으로 미리 학습되어 있어서 우리는 그대로 쓰면 됩니다.

**ImageNet 사전학습 (pretrained)**  
ImageNet은 1,400만 장의 사진 데이터셋. 여기서 미리 학습된 모델은 "고양이가 뭔지, 자동차가 뭔지" 이미 알고 있음.  
우리는 그 모델을 가져다가 **커피 콩만 추가로 가르치면** 빨리 학습됩니다.

**동결 (freeze) / 동결 해제 (unfreeze)**  
- **동결**: 모델의 일부분이 **학습되지 않게 잠그는 것**
- **동결 해제**: 다시 학습 가능하게 풀어주는 것
- 우리는 처음 2 epoch는 backbone을 동결하고 마지막 분류 부분만 학습 → 그 후 풀어서 전체 학습

### 평가 지표

**정확도 (Accuracy)**  
맞힌 개수 ÷ 전체 개수. 예: 100장 중 94장 맞히면 정확도 94%.  
직관적이지만 클래스가 불균형하면 함정이 있음.

**F1 점수 (F1 score)**  
정밀도(Precision)와 재현율(Recall)을 균형 있게 합친 점수. **0~1 사이**, 1에 가까울수록 좋음.  
**클래스별 성능을 더 정직하게** 보여줍니다. 0.94 = 매우 좋음, 0.80 = 좋음, 0.50 = 어려움.

**Macro F1**  
**모든 클래스의 F1을 평균**낸 값. 어떤 클래스가 데이터가 적든 많든 똑같이 1표.  
→ 데이터 불균형이 있어도 공평한 평가.

**Confusion Matrix (혼동 행렬)**  
"어떤 정답을 어떤 예측으로 헷갈렸나" 보여주는 표.  
대각선이 정답이고, 대각선 밖이 오답입니다. **모델의 약점을 한눈에** 볼 수 있음.

### 배포 관련

**PyTorch (파이토치)**  
페이스북이 만든 AI 프레임워크. **연구/학습**에 가장 많이 씀. 우리도 학습은 다 PyTorch로 했음.

**ONNX (오닉스)**  
**Open Neural Network Exchange**. AI 모델을 위한 **표준 포맷**.  
PyTorch / TensorFlow 등 어디서 만든 모델이든 ONNX로 바꾸면 어디서나 돌릴 수 있음.

**ONNX Runtime**  
ONNX 파일을 실행하는 **빠른 엔진** (Microsoft가 개발). PyTorch보다 가볍고 빠름.

**추론 (Inference)**  
학습이 끝난 모델로 **새 데이터에 대해 답을 예측하는 것**. "예측"이라고도 함.  
학습은 무겁지만 추론은 빨라야 함 (실제 서비스니까).

**FPS (Frames Per Second)**  
초당 처리 가능한 사진 장수. 30 FPS = 1초에 30장 처리.  
영상이 보통 30 FPS이니까 **30 FPS 이상이면 실시간 처리 가능**.

**CPU / GPU**  
- **CPU**: 일반 컴퓨터 두뇌. 느리지만 어디나 있음.
- **GPU**: 그래픽카드. AI 학습/추론에 훨씬 빠르지만 비쌈.
- 우리 프로젝트는 **CPU에서도 충분히 빠름** (ONNX 덕분).
